# 📊 부서별 년도별 예산 기안·결재·재정부이관 시스템 기획안

본 기획안은 원천교회 재정부 시스템(`report-form-ui` / `report-server`)에서 **부서별 회계가 차기년도 예산을 기안하고, 다단계 전자결재를 거쳐 최종 재정부 이관 시 기준 예산(`budgets`)에 자동 반영**되는 전체 프로세스와 화면 설계를 정의합니다.

새로 정립된 **UI/UX 디자인 시스템 가이드라인(목록조회 / 팝업 / 처리성 3대 대표화면 규격 및 부연설명 문구 최소화 원칙)**을 100% 준수하여 기획되었습니다.

## 1. 업무 프로세스 및 생명주기 (Workflow)

```mermaid
flowchart LR
    A[1. 예산 기안 작성<br/>(부서 회계)<br/>당해년도 예산 자동세팅 ➔ 세목별 수정] -->|결재 상신| B[2. 기존 '내결재목록' 통합 결재<br/>(부서장/위원장/당회장)<br/>청구지출건과 동일 큐에서 승인]
    B -->|승인 완료| C[3. 재정부 검토 및 이관<br/>(재정부 관리자)<br/>내결재목록에서 최종 이관]
    B -->|반려| A
    C -->|재정부 이관 완료| D[4. 기준 예산 자동 반영<br/>budgets 테이블 Upsert]
    D --> E[전사 예산집행 시스템 연동<br/>BudgetsGrid / DeptBudgetStatus]
```

### 단계별 핵심 업무 규칙
1. **기안 (작성/상신 - 부서 회계)**
   - 대상 회계연도(예: 2027년)와 부서 선택 시, **당해년도(2026년)의 기존 예산(`budgets`) 데이터를 자동 조회하여 2027년 편성액에 기본값으로 세팅**합니다.
   - **관 ➔ 항 ➔ 목 ➔ 세목(4단계)** 계층 체계를 모두 표시하며, 최하위 계정(세목/목)의 금액을 수정하면 상위 계정으로 실시간 자동 합산됩니다.
2. **통합 결재 (다단계 전자결재 - 결재권자)**
   - 별도의 결재 화면을 두지 않고, **기존 「내결재목록 조회」(`ApprovalListPage.vue`, 모바일 포함)에 지출결의서와 동일한 큐로 통합**됩니다.
   - 문서 유형에 **`예산편성서`**로 노출되며, 결재 클릭 시 [ReportPreview.vue](file:///Users/baeseokin/report-form-ui/src/components/ReportPreview.vue)에서 예산편성 양식 확인 후 전자서명 승인/반려합니다.
3. **재정부 이관 및 기준 예산 자동 반영**
   - 모든 결재선이 승인 완료되면 재정부의 「내결재목록 조회」에 이관 대기로 표시됩니다.
   - 재정부에서 최종 확인 후 `재정부 이관완료`를 실행하면 대상연도 공식 기준 예산(`budgets` 테이블)에 자동 INSERT/UPDATE(Upsert) 반영됩니다.

## 4. 데이터베이스 및 백엔드 API 설계 (Database & APIs)

### 4.1 신규 테이블 설계

#### 1) `budget_requests` (예산 기안 마스터)
```sql
CREATE TABLE IF NOT EXISTS budget_requests (
  id INT AUTO_INCREMENT PRIMARY KEY,
  year INT NOT NULL COMMENT '대상 회계연도 (예: 2027)',
  dept_id INT NOT NULL COMMENT '신청 부서 ID',
  dept_name VARCHAR(100) NOT NULL COMMENT '부서명',
  author_id INT NOT NULL COMMENT '기안자 ID',
  author_name VARCHAR(50) NOT NULL COMMENT '기안자명',
  title VARCHAR(200) NOT NULL COMMENT '예산안 제목 (예: 2027년도 유초등부 예산편성안)',
  total_amount BIGINT NOT NULL DEFAULT 0 COMMENT '편성 요청 총액',
  prev_year_amount BIGINT NOT NULL DEFAULT 0 COMMENT '전년도 예산 총액',
  status ENUM('작성중', '결재진행중', '결재완료', '결재반려', '재정부이관완료') DEFAULT '작성중',
  comment TEXT NULL COMMENT '기안 총괄 설명 및 특이사항',
  rejection_reason TEXT NULL COMMENT '반려 사유',
  transferred_at DATETIME NULL COMMENT '재정부 이관 일시',
  transferred_by VARCHAR(50) NULL COMMENT '재정부 이관 처리자',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uq_dept_year (dept_id, year) COMMENT '부서별 동일연도 1건 원칙'
);
```

#### 2) `budget_request_items` (예산 편성 계정별 상세)
```sql
CREATE TABLE IF NOT EXISTS budget_request_items (
  id INT AUTO_INCREMENT PRIMARY KEY,
  request_id INT NOT NULL COMMENT 'budget_requests.id 외래키',
  category_id INT NOT NULL COMMENT '계정 카테고리 ID',
  category_name VARCHAR(100) NOT NULL COMMENT '계정명',
  level ENUM('관', '항', '목', '세목') NOT NULL,
  prev_amount BIGINT DEFAULT 0 COMMENT '전년도 예산액',
  request_amount BIGINT NOT NULL DEFAULT 0 COMMENT '편성 요청 예산액',
  diff_amount BIGINT DEFAULT 0 COMMENT '증감액',
  calc_basis VARCHAR(500) NULL COMMENT '산출 근거 / 산출 공식',
  sort_order INT DEFAULT 0,
  FOREIGN KEY (request_id) REFERENCES budget_requests(id) ON DELETE CASCADE
);
```

#### 3) 결재선/서명 이력 연동
- 기존 `approval_history` 테이블 구조(request_id, approver_role, approver_name, signature_url, status, comment)를 공유하거나 `budget_approval_history`로 독립 분리하여 완벽한 다단계 전자서명 추적 보장.

### 4.2 재정부 이관 시 '기준 예산(`budgets`) 자동 반영' 로직
재정부 이관 승인 API (`POST /api/budgetRequests/:id/transfer`) 호출 시 트랜잭션:
1. `budget_requests.status = '재정부이관완료'`, `transferred_at = NOW()` 업데이트
2. `budget_request_items`의 말단 계정(세목/목) 항목들을 추출
3. 기존 전사 기준 예산 테이블인 `budgets`에 Upsert:
   ```sql
   INSERT INTO budgets (category_id, year, budget_amount)
   VALUES (?, ?, ?)
   ON DUPLICATE KEY UPDATE budget_amount = VALUES(budget_amount);
   ```
4. **결과**: `BudgetsGrid.vue`, `DeptBudgetStatus.vue` 및 향후 지출결의서 작성 시 해당 연도 기준 예산으로 즉시 활성화!
